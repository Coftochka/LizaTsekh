# Лиза Цех — сайт

Сайт — набор статических файлов. На сервере его обслуживает nginx:

- `/` отдаёт страницу выбора направления;
- `/portfolio/` отдаёт исходное портфолио и его статические ресурсы;
- `/interfaces/` отдаёт портфолио интерфейсов и его статические ресурсы;
- `/yandex_54ab1d330ea02f48.html` доступен для верификации Яндекса.
- `/robots.txt` и `/sitemap.xml` помогают поисковым роботам обнаружить
  канонические страницы сайта.

Конфигурация nginx находится в [nginx/lizatsekh.ru.conf](nginx/lizatsekh.ru.conf).

## Деплой

Заполните приватный файл `.env` по образцу `.env.example`, затем запустите:

```bash
./deploy.sh
```

Скрипт синхронизирует файлы, устанавливает nginx-конфиг, проверяет его и
перезагружает nginx. Для автоматического применения конфигурации SSH-пользователь
должен иметь ограниченные права `sudo` на эти команды.

`deploy.sh` отправляет текущие файлы рабочей папки: он **не** выполняет `git pull`
и не пытается разрешать Git-конфликты. Удаление файлов на сервере также намеренно
не выполняется (`rsync` запускается без `--delete`).

Проверка после деплоя:

```bash
curl -I https://lizatsekh.ru/portfolio/
```

## Какие файлы доступны из интернета

Nginx не публикует всю папку проекта. У сайтов отдельные каталоги:

- `portfolio/` — исходное портфолио;
- `interfaces/` — портфолио интерфейсов;
- `index.html` в корне — только страница выбора.

В конфиге явно разрешены только:

- страницы: `/`, `/portfolio/` и `/interfaces/`;
- общий favicon: `/favicon.svg` (файл `portfolio/img/favicon.svg`);
- скрипты: `/portfolio/support.js` и `/portfolio/stat-roll.js`;
- медиа: всё внутри `/portfolio/img/` и `/portfolio/fonts/`;
- компоненты и нужные ассеты из белого списка `/interfaces/`;
- файлы для поисковых роботов: `/robots.txt`, `/sitemap.xml` и файл верификации
  Яндекса `/yandex_54ab1d330ea02f48.html`.

Исходники, `.env`, Git-метаданные, логи и любые другие пути должны оставаться
недоступны. Например, `/interfaces/src/` и `interfaces/Запустить.command` не
публикуются. При добавлении нового типа публичных файлов нужно отдельно добавить
для него `location` в `nginx/lizatsekh.ru.conf`.

## Изображения и видео в `index.html`

Файлы изображений и роликов исходного портфолио хранятся в `portfolio/img/` и при деплое синхронизируются
через `rsync`. Путь в HTML указывается относительно `index.html`, например:

```html
<img src="img/photo-grey.jpg" alt="Лиза Цех">
```

### Динамические изображения

Разметка внутри `<x-dc>` рендерится JavaScript-движком из `support.js`. Если
`src` строится из шаблонного значения, нельзя писать `src="{{ value }}"`:
браузерный preload scanner может попытаться загрузить буквальный адрес
`{{ value }}` ещё до рендера.

Используйте `data-dc-src`:

```html
<img data-dc-src="{{ it.src }}" alt="">
```

`support.js` намеренно преобразует `data-dc-src` в настоящий `src` после
вычисления шаблона. Не удаляйте эту обработку без одновременного изменения всей
динамической разметки.

### Главный ролик

Главный ролик — `img/lr/hero.mp4`. Он находится внутри `<x-dc>`, поэтому тоже
использует `data-dc-src`, хотя путь постоянный:

```html
<video data-dc-src="img/lr/hero.mp4" preload="auto" ...></video>
```

Это важно: обычный `src` позволил бы исходному шаблону начать загрузку, а после
рендера новый `<video>` мог бы загрузить тот же файл второй раз. `data-dc-src`
создаёт `src` только у итогового элемента. `preload="auto"` оставлен специально,
чтобы этот один итоговый элемент заранее загрузил ролик.
